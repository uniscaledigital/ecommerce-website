# Codebase Concerns
**Analysis Date:** 2026-11-05

## Tech Debt

**Deprecated Shopify Storefront API Version Fallback (2025-01):**
- Issue: The application hardcodes a fallback to `2025-01` across API routes and client fetch helpers when `SHOPIFY_STOREFRONT_API_VERSION` is not specified in environment variables. Shopify Storefront API versions follow an annual 1-year lifecycle; by late 2026, `2025-01` is past its 12-month support window and sunsetted.
- Files: `website/src/lib/shopify/index.ts:15`, `website/src/app/api/cart/route.ts:15`, `website/src/app/api/shopify/route.ts:7`
- Impact: If the environment variable is missing in production, calls route to an unsupported GraphQL endpoint version, risking schema incompatibility errors, dropped fields, or Shopify API rejection.
- Fix approach: Update default fallback to an active 2026 calendar version (`2026-01`, `2026-04`, or `2026-10`), and document `SHOPIFY_STOREFRONT_API_VERSION=2026-10` in `.env.example`.

**Remix Framework Dependency Mismatch (@shopify/hydrogen) in Next.js:**
- Issue: `website/package.json:14` specifies `"@shopify/hydrogen": "^2026.10.2"`. However, `@shopify/hydrogen` is an opinionated full-stack framework built specifically on React Router v7 / Remix for Shopify Oxygen, and is completely unimported and unused across the Next.js 15 App Router codebase. Meanwhile, the required framework-agnostic libraries (`@shopify/hydrogen-react` and `@shopify/storefront-api-client`) are not installed.
- Files: `website/package.json:14`
- Impact: Bloats dependencies (~50MB+ in `node_modules`), creates confusion regarding framework architecture, and blocks proper adoption of official Shopify React primitives (`<ShopifyProvider>`, `<CartProvider>`, `<ShopPayButton>`).
- Fix approach: Remove `@shopify/hydrogen` from `website/package.json` dependencies and install `@shopify/hydrogen-react` and `@shopify/storefront-api-client`.

**Simulated Client-Side Authentication & Plaintext LocalStorage:**
- Issue: `website/src/context/AuthContext.tsx` simulates customer authentication by persisting a boolean flag and mock customer profile directly to browser `localStorage` (`irish_grocer_auth` and `irish_grocer_customer`). Submitting any email at `/account/login` logs in without credential verification or token validation.
- Files: `website/src/context/AuthContext.tsx:87-128`, `website/src/app/account/login/page.tsx`, `website/src/app/account/page.tsx`
- Impact: No authentic customer authentication or data security exists; mock customer orders and details are visible to anyone typing an arbitrary email; cannot synchronize customer order history or profiles with live Shopify accounts.
- Fix approach: Implement Shopify Customer Account API using OAuth 2.0 PKCE flow, proxying authorization callbacks through Next.js server route handlers (`website/src/app/api/auth/`) and storing access tokens in secure `HttpOnly`, `SameSite=Lax` cookies.

**Local Filesystem Order Enquiry Storage in Serverless Environment:**
- Issue: `website/src/lib/enquiry/storage.ts` writes customer hamper and special order enquiries to `process.cwd()/.data/enquiries.json` using `node:fs/promises`.
- Files: `website/src/lib/enquiry/storage.ts:11-38`, `website/src/app/api/enquiry/route.ts:57-63`
- Impact: In modern serverless deployments (Vercel, AWS Lambda, Cloudflare), the server root filesystem is read-only, causing runtime `EROFS` crashes when users submit enquiries. On environments with ephemeral storage, records disappear when container instances restart, and concurrent requests cause race conditions and file corruption.
- Fix approach: Replace filesystem JSON storage with a persistent database (PostgreSQL via Prisma/Drizzle, Supabase) or forward enquiries directly via transactional email (Resend, SendGrid) or Shopify Draft Orders API.

## Known Bugs

**B2B Gated Pricing Discrepancy with Schema.org JSON-LD:**
- Symptoms: Unauthenticated human visitors see "Log in to view prices" and cannot add products to cart, while search engine crawlers receive full price data (`offers: { price: product.priceRange.minVariantPrice.amount }`) in schema.org JSON-LD generated by `website/src/app/products/[handle]/page.tsx:56`.
- Files: `website/src/components/products/ProductCard.tsx:107-147`, `website/src/app/products/[handle]/ProductDetailsClient.tsx:152-164`, `website/src/app/products/[handle]/page.tsx:43-71`
- Trigger: Visiting any catalog or product page without an active simulated login session.
- Workaround: Visitors must navigate to `/account/login` and submit an email to unlock visible prices and cart buttons.

**In-Memory Sliding-Window Rate Limiter Reset on Serverless Cold Starts:**
- Symptoms: Rate limit counters reset intermittently across requests, and distributed requests bypass rate limits.
- Files: `website/src/lib/security/rateLimit.ts:6-21, 36-92`
- Trigger: Multiple concurrent requests distributed across separate serverless execution environments or lambda cold starts.
- Workaround: None in application layer; requires deploying behind a CDN WAF or integrating a centralized cache.

## Security Considerations

**In-Memory Rate Limiting & Header-Based IP Spoofing:**
- Risk: The rate limiter stores state in a process-level JavaScript `Map`. In serverless or containerized environments, instances do not share memory, rendering limits ineffective against distributed abuse. Furthermore, client IP is extracted via `request.headers.get("x-forwarded-for")?.split(",")[0]` without verifying trusted upstream proxies, enabling attackers to spoof IP addresses via custom headers.
- Files: `website/src/lib/security/rateLimit.ts:45-48`, `website/src/app/api/cart/route.ts:44-54`, `website/src/app/api/shopify/route.ts:10-21`, `website/src/app/api/enquiry/route.ts:7-18`
- Current mitigation: Payload size cap (10KB), strict GraphQL query allowlist (`validateShopifyPayload`), and sliding-window rate tracking.
- Recommendations: Migrate to Upstash Redis (`@upstash/ratelimit`) or edge middleware, and rely on platform-trusted client IP headers (such as `x-vercel-forwarded-for` or `cf-connecting-ip`).

**Local Filesystem Enquiry Storage Security:**
- Risk: Writing unauthenticated customer form submissions to local disk files creates risk of disk space exhaustion or file locking contention.
- Files: `website/src/lib/enquiry/storage.ts`
- Current mitigation: Validation schemas limit customer name (100 chars), email (255 chars), address (500 chars), and cap file history to 500 records.
- Recommendations: Store enquiry data in an encrypted, managed cloud database with TLS in transit and at rest.

**Storefront API Token Handling:**
- Risk: Public Storefront API tokens vs private/delegate tokens must be kept strictly separated.
- Files: `website/src/lib/shopify/index.ts:14`, `website/src/app/api/cart/route.ts:14`, `website/src/app/api/shopify/route.ts:6`
- Current mitigation: Secrets are accessed via server environment variables (`SHOPIFY_STOREFRONT_ACCESS_TOKEN`) without `NEXT_PUBLIC_` prefixes in API handlers.
- Recommendations: Ensure `.env.local` is never committed and create automated CI secret scanning to prevent token leakage.

## Performance Bottlenecks

**Monolithic File Read/Write in Order Enquiries:**
- Problem: `persistOrderEnquiry` reads the entire JSON file, parses it, modifies the array, re-serializes the entire JSON string, and rewrites the file on every single enquiry.
- Files: `website/src/lib/enquiry/storage.ts:18-34`
- Cause: Lack of database indexing or append-only transactional logging.
- Improvement path: Migrate to a relational database with indexed timestamps or an asynchronous queue.

**Large Video and Static Media Delivery:**
- Problem: The homepage hero loads an ambient MP4 video (`hero-background-h264.mp4`, ~4.1MB) and high-resolution raster images (`background-img.png`, ~2.0MB; `footer background.png`, ~1.3MB) directly from public static storage.
- Files: `website/src/components/home/HeroSection.tsx:32-47`, `website/src/components/layout/Footer.tsx:18`
- Cause: Uncompressed assets served directly from local static storage rather than a media CDN with adaptive bitrate or AVIF/WebP next-gen formats.
- Improvement path: Host video on an external streaming CDN (Cloudflare Stream, Mux) with HLS streaming, and ensure background PNGs are converted to optimized WebP format with responsive sizing.

## Fragile Areas

**Dual Cart Synchronization (Local Optimistic State vs. Shopify Server):**
- Files: `website/src/context/CartContext.tsx:70-125, 480-530`, `website/src/lib/shopify/cartFormatter.ts`
- Why fragile: `CartContext` maintains local state and enqueues background sync tasks to `/api/cart`. If a network interruption occurs, or if the Shopify cart expires (Shopify carts expire after 14 days of inactivity), local cart IDs (`cart-item-...`) conflict with Shopify GraphQL global IDs (`gid://shopify/CartLine/...`), potentially triggering 404s and clearing the cart unexpectedly.
- Safe modification: Ensure thorough error handling and state rollbacks when testing cart changes; preserve user cart items even if upstream sync fails.
- Test coverage: Unit tests exist in `website/tests/remediation.test.ts` for demo mode formatting, but network failure recovery and Shopify cart expiration scenarios are untested.

**Demo vs. Production Checkout Boundary:**
- Files: `website/src/context/CartContext.tsx:534-550`, `website/src/components/cart/DemoCheckoutModal.tsx`, `website/src/components/enquiry/OrderEnquiryModal.tsx`
- Why fragile: If a user attempts checkout in production and `checkoutUrl` is invalid, the system displays an error banner and automatically opens the Order Enquiry modal, shifting the user journey from direct payment to a manual inquiry.
- Safe modification: Provide granular user-facing notifications distinguishing network failure, inventory exhaustion, and cart synchronization errors.
- Test coverage: No end-to-end checkout redirection tests exist.

## Scaling Limits

**In-Memory Rate Limiting:**
- Current capacity: Single-instance process memory table (30-60 requests/min per IP).
- Limit: Ineffective across multi-pod or serverless deployments.
- Scaling path: Migrate to Redis or edge-based rate limiting.

**Local Filesystem Enquiry Storage:**
- Current capacity: Maximum 500 records in `website/src/lib/enquiry/storage.ts`.
- Limit: Read-only filesystems in serverless cloud environments prevent writes; concurrent requests risk file corruption.
- Scaling path: Migrate to cloud database or serverless queue.
